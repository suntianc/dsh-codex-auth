# Preserve Codex turn continuity during automatic compaction

Status: **accepted**

The opt-in `dsh-codex-auth/compaction` Adapter extends the manual Dual Checkpoint operation to Basic's pressure and provider-confirmed context-overflow entries without taking ownership of their lifecycle. Plugin application installs read-only `agent/pre-step` and `agent/request-error` boundary scopes before constructing `BasicCompactionEngine`; the subclass then wraps dynamically dispatched `compactIfNeeded()` in the same Host coordinator used by manual operation and immediately delegates to `super.compactIfNeeded()`. Basic remains authoritative for trigger policy, tool-result pruning, balanced range selection, retries and overflow caps, durable marker ordering, strict shrink, surface replacement, and cancellation. Explicit-region compaction remains Portable-only.

The `openai-codex` Adapter installs a read-only `llm/stream` waterfall listener. It tests the exact deep-frozen `GenerateOptions` object with DSH's process-local `isAgentLoopRequest()` identity before `LlmRuntime` can project or clone the request, records only session/route/model in `AsyncLocalStorage`, and calls `next()` without replacing the request. Adapter and provider code consume that scope; they never test a later projected request object for loop identity. A second request scope binds the prepared Adapter generation so route replacement cannot mix an old continuation with a new provider snapshot.

A successful native v2 response may carry `x-codex-turn-state`. The transport returns that value only in memory and only after a successful terminal response with exactly one accepted compaction artifact. It is excluded from the Native Checkpoint codec, compatibility digest, diagnostics, and every durable value. The coordinator records a candidate only for an inline automatic operation. It arms the candidate only after inherited `compactIfNeeded()` returns a committed result containing the Native block; strict-shrink fallback, Portable-only success, abort, or any later Basic error clears it. Manual `/compact`, direct `compactIfNeeded()`, and `compactRegion()` never arm a candidate.

An armed Codex Turn Continuation is keyed by session, `openai-codex` route, exact model, domain-separated account hash, and Adapter generation. It is removed before dispatch to exactly the next matching Agent-loop provider request. A 60-second unref'd timer expires it; the first mismatching eligible request, authentication failure, iterator teardown, request error/abort, route replacement, or plugin disposal erases it. Requests without Agent-loop identity—including Portable summaries, session titles, auxiliary calls, and direct maintenance—neither consume nor invalidate it. Concurrent sessions retain separate request scopes, payload captures, credentials, replay plans, and continuation entries.

Long Context Mode remains a model-capacity advertisement only. It can defer the pressure boundary by changing the reported context window, but it does not participate in native eligibility, codec/retention generations, compatibility digest, or turn-continuation matching.

Testing a cloned Adapter request for loop identity was rejected because DSH deliberately keeps the mark process-local to the original loop envelope. Persisting the continuation beside a checkpoint, placing it in a header cache, logging it, exposing it through browser state, or letting auxiliary calls consume it was rejected because provider turn state is ephemeral and secret-bearing. Replacing ordinary pi-ai streaming or copying Basic's automatic listeners was rejected because both would create competing lifecycle owners.

This decision remains pinned to DSH / Basic `0.1.1-rc.2` and pi-ai `0.82.1`. A future supported provider-native checkpoint and turn-continuation Seam should replace the boundary scopes, direct transport, marker replay, and process-local handoff while retaining Portable Checkpoints as the rollback representation.
