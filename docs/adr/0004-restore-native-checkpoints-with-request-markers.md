# Restore Codex Native Checkpoints with Host-only request markers

Status: **accepted**

An already durable Dual Checkpoint is restored by the ordinary `openai-codex` Adapter, not by a second compaction engine or a DSH core content type. The package declaration-merges `codex-native-checkpoint` into `@deepseek-ai/dsh-llm`'s `ContentBlockMap` and exports its versioned Host codec from `dsh-codex-auth/native-checkpoint`. The opaque JSON carrier records exact schema, codec and retention generations; provider/model provenance; a domain-separated account hash; a canonical compatibility digest; replay estimate and optional usage facts; and provider-owned canonical text-only retained-user Responses items ending in one opaque compaction item. Only those replacement items are forward-extensible. The enclosing schema is strict, lossless, bounded to 2 MiB, and rejects credentials, headers, raw turn state, request-local metadata, and unsafe object keys.

`CodexAuthAdapter` wraps both `super.prepareCall()`'s registration-bound stream and its direct `stream()` path. It clones checkpoint-bearing `GenerateOptions` and messages rather than mutating DSH's frozen call state. Every complete Basic-framed checkpoint with exactly one valid native block becomes a marker-only user message before pi-ai conversion; malformed mixtures become text-only Portable messages. An Adapter-owned `AsyncLocalStorage` scope carries the generated marker, candidate, Portable fallback, routed model, and hashed account identity while each lazy stream iterator is advanced. It is request-local, collision-safe, cleared on iterator teardown, and never persisted or logged.

The plugin-owned pi-ai provider wrapper composes `onPayload` in a fixed order: restore every exact marker item, await callbacks that were already supplied, then validate the effective final payload. A compatible marker is replaced in place by cloned canonical native items. An incompatible marker is replaced by one ordinary Portable user item. Missing, duplicate, embedded, leaked, or unconsumed generated markers fail before fetch, while ordinary marker-like text that was not generated for that request remains ordinary text. A final callback may not change native compatibility controls or reintroduce the Portable form beside native state.

Replay compatibility includes the exact provider, model, hashed Codex account, instructions, tool schema and policy, reasoning/text controls, service tier, and codec/retention generations. It excludes cache keys, request/session identifiers, headers, and Long Context Mode. The converter is pinned to DSH LLM and `dsh-llm-pi-ai` `0.1.1-rc.2` plus pi-ai `0.82.1`; another installed pair strips the opaque block and delegates the Portable text. This conditional pin keeps the normal capability bundle's broader baseline and leaves `cordis.patch.yml` unchanged.

DSH's compaction conversation projection is already text-only: Portable summary blocks produce the visible compaction node, while the opaque custom block is absent from presentation and copy content. The plugin's public client `apply()` seam is tested to register exactly its settings and image views, with no conversation or custom-block renderer competing with that projection. Native state creation, a remote v2 compaction request, automatic triggers, v1, live account probes, and changes to the custom compaction Adapter remain separate work.
