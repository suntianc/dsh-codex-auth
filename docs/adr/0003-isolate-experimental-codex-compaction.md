# Isolate experimental Codex compaction behind a custom preset

Status: **accepted** for activation and Basic ownership; the Portable-only creation state is superseded by [ADR 0005](0005-create-dual-checkpoints-inside-basic-manual-transactions.md).

The experimental Codex compaction Adapter is exported from `dsh-codex-auth/compaction` and selected only by a user/deployer-authored custom agent preset. The normal capability-bundle patch and shipped DSH presets keep `@deepseek-ai/dsh-compaction-basic`. The custom preset replaces that row, rather than accompanying it, so exactly one Adapter owns the isolated `ctx.compaction` Interface while the stock compact command and tool-result pruner remain composed around it. This explicit opt-in is necessary because the shipped compaction row is nested inside a preset group and a bundle patch cannot safely replace it.

`CodexCompactionEngine` subclasses `BasicCompactionEngine` and reserves only its protected summarization Seam. It delegates the current Portable-only result to `super.summarize()` and inherits range selection, trigger policy, tool pairing, durable locks, stability checks, strict shrink, event ordering, surface replacement, overflow behavior, errors, and manual flush. The package now owns a declaration-merged custom carrier for restoring an already durable Dual Checkpoint, but this Adapter does not create that block yet. The carrier remains experimental rather than a DSH-wide content standard; when later native creation is added, DSH 0.1.2-alpha.5 Basic framing can commit it beside Portable text in one summary event and replacement message.

This compromise is pinned exactly to DSH 0.1.2-alpha.5 across the agent, compaction, Basic engine, LLM, pi-ai Adapter (`@deepseek-ai/dsh-llm-pi-ai`), session, and token-meter packages, plus `@earendil-works/pi-ai` 0.84.4. It depends on observed alpha.5 framing and projection behavior that is not a stable provider-native checkpoint contract, so a mixed or newer runtime must fail loudly until the complete compatibility matrix is rerun. Operators can roll back by selecting a shipped preset; Portable Checkpoints remain readable and no profile migration is required.

Editing DSH core or installed packages, rewriting generated presets, monkey-patching prototypes, importing private/deep converters, replacing the ordinary pi-ai stream, and copying Basic lifecycle code were rejected because they bypass supported plugin Interfaces and create an unreviewable second compaction transaction. Automatic bundle activation was rejected because it would silently change existing sessions and can race the shipped Basic owner. An independent sidecar store was rejected because it would lose Basic's atomic checkpoint transaction.

When DSH exposes a supported provider-native checkpoint Seam, delete the declaration-merged carrier, request side channel, direct native transport, compatibility assertion, custom Adapter, and custom-preset replacement. Migrate replay through the upstream Interface and retain Portable Checkpoints as the provider-neutral recovery path.
