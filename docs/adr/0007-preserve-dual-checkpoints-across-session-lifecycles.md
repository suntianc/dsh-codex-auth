# Preserve Dual Checkpoints across Session lifecycle boundaries

Status: **accepted** for the experimental alpha.5-compatible compaction path.

A Dual Checkpoint is immutable ordinary Session data: Basic commits Portable text and the versioned Codex Native block atomically, and later requests only transform detached copies. JSON persistence, alpha.5's `Session.snapshotEvents()` / `Session.fromRestore(..., inheritedEventCount)` contract, and `SessionStore.fork()` therefore preserve the same candidate without provider-specific Session rewriting; persistence carries the inherited-prefix count separately from the event snapshot. A compatible Codex request may replay Native after restart or in a fork; a later compaction may also expand it and commit a fresh checkpoint there. An incompatible request or earlier checkpoint contributes the sibling Portable text without preventing a new compatible checkpoint.

Compatibility is decided from the final effective Responses payload. Marker restoration runs before a composed payload callback so existing callbacks keep their established input view; after the callback, the replay coordinator re-evaluates model, hashed account identity, instructions, tools and tool policy, reasoning, text configuration, and service tier. It may downgrade provisional Native items to one Portable item or upgrade provisional Portable back to Native. Request IDs, prompt-cache keys, transient headers, turn state, and Long Context Mode remain routing/capacity facts and do not enter the digest. A callback may not erase or move the checkpoint input, duplicate a representation, or make Native and Portable coexist. Pi-ai `0.84.4` can add an `additional_tools` input item for deferred GPT-5.6 tools; because the current compatibility digest does not model that semantic history, its presence forces Portable replay and prevents new Native creation.

Before a repeated v2 trigger is appended, marker restoration expands every compatible checkpoint in the selected prefix once and in original item order; incompatible checkpoints materialize exactly one Portable user item. The retained-prefix builder then keeps eligible recent text-only user groups under its versioned 64,000-token budget and appends the new opaque artifact last. Basic alone replaces the selected surface prefix, preserves every later DSH tail message, and owns repeated-pressure convergence or its inherited bounded failure.

Provider switching does not consume or mutate durable state. The shipped PiAiAdapter and direct DeepSeek Adapter project the declaration-merged block away and put Portable text on their wire. Returning to the compatible Codex route before another compaction can therefore use the retained Native state. Arbitrary third-party Adapters that reject unknown blocks remain outside this plugin-only guarantee.

Adapter generation replacement and plugin disposal invalidate stale prepared and in-flight replay eligibility together with one-shot turn continuation. Those calls degrade to Portable; a new generation can reconsider the unchanged durable checkpoint. Selecting stock Basic is likewise a rollback rather than a migration: existing Sessions remain usable, and incompatible/account-changed replay follows Portable text.

The codec persists only the domain-separated account hash and rejects credentials, namespaced or wrapped token/auth/header fields, raw turn state, raw/namespaced account or routing identifiers, unsafe JSON, and oversized carriers. Its `text: ''` presentation sentinel makes alpha.5 generic Chat and Trajectory rendering treat the opaque block as empty content, while stock conversation presentation continues to use Portable text. The opaque bytes nevertheless remain sensitive Session/RPC/export data and must be handled as such. Pre-issue-18 worktree fixtures without the sentinel remain Host-decodable because this feature was not released, but they are outside the generic Trajectory presentation guarantee and require fixture migration before viewing.
