# Create Dual Checkpoints inside Basic manual transactions

Status: **accepted**

The opt-in `dsh-codex-auth/compaction` Adapter creates a Codex Native Checkpoint only during `BasicCompactionEngine.compactNow()`. The override opens a Host-only manual-operation scope and then delegates the complete transaction to `super.compactNow()`. Its inherited summarization hook must finish `super.summarize()` first. Automatic pressure/overflow entry points and explicit-region compaction remain Portable-only. This keeps Basic as the sole owner of range selection, tool pairing, durable locking, stability checks, strict shrink, event ordering, surface replacement, cancellation, and manual flush.

A request-local coordinator joins the protected summarization Seam to the existing `openai-codex` Adapter without creating a public provider-native compaction Interface. While the successful Portable call is active, the Adapter records only in memory its resolved Codex Login State, exact provider/model/session identity, public header inputs, transport policy, and final payload after Native marker restoration and existing payload callbacks. The coordinator retains Basic's compaction signal rather than pi-ai's stream-watchdog signal. Sensitive references are cleared when the operation settles.

After Portable success, an eligible nonempty image-free current-surface prefix produces one dedicated Host-side Responses v2 request. The implementation captures, validates, and removes rc.2 Basic's actual final synthetic compaction instruction rather than copying private Basic source; replay recognizes complete rc.2 framing through pinned SHA-256 digests. It copies only compatible model, input, instructions, tools, tool controls, reasoning, text, service-tier, and prompt-cache fields, forces streaming non-storage semantics plus encrypted-reasoning inclusion, and appends one transient `compaction_trigger`. A narrow compact-header builder reuses the already resolved token, attributes DSH, and supplies installation/session/window compatibility metadata; manual compaction never sends, stores, or arms turn state. Ordinary inference remains entirely on pi-ai's existing transport.

The dedicated SSE decoder accepts only a successful HTTP response with terminal `response.completed` and exactly one nonempty opaque `compaction` output. Other completed output items are counted and ignored. The client retains eligible recent text-only user items newest-first under the versioned 64,000-token estimate, safely truncates one boundary group's text prefix, and appends the opaque artifact last. The resulting credential-free state must pass the versioned codec, 2 MiB block limit, and a conservative shrink precheck before it is added beside Portable text. Basic then commits both representations in its existing summary/replacement transaction.

Any ordinary native ineligibility, transport failure, timeout, rate limit, HTTP/protocol failure, malformed stream, incompatible payload, oversize state, or shrink failure returns the already valid Portable result. Cancellation remains cancellation, and Portable failure never starts a native request. Native transport has no per-transaction retry. A process-local breaker keyed by hashed account identity, exact model, endpoint, and codec generation limits repeated native failures without disabling ordinary inference or Portable compaction; authentication, oversize-state, and strict-shrink fallbacks do not count. Host diagnostics expose only compaction identity, manual trigger, codec generation, model, eligibility/status/fallback class, breaker state, timing, counts, byte/token estimates, and usage source/counts; authentication rejection emits the existing `codex login` remediation while prompts, tools, headers, credentials, canonical items, and encrypted content stay out of logs.

Starting native generation before Portable success was rejected because it could waste quota and create a remote-only result with no safe provider-neutral recovery. Running both calls in parallel was rejected because it permits concurrent same-session Codex requests and complicates cancellation. Replacing pi-ai's ordinary stream, copying Basic's transaction, persisting a sidecar, reading authentication a second time, activating through `cordis.patch.yml`, or editing DSH core were rejected because they violate the plugin-first seam and atomicity constraints.

This is a pinned compromise for DSH / Basic `0.1.1-rc.2` and pi-ai `0.82.1`. When DSH and its provider Adapter expose a supported provider-native checkpoint operation, migrate creation, replay ownership, accounting, and diagnostics to that Interface; then delete the Host request coordinator, direct v2 transport, declaration-merged carrier, compatibility pin, and custom Basic subclass while retaining Portable Checkpoints as the rollback representation.
